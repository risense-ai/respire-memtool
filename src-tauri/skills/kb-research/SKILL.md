# 知识库调研（kb-research）

任务正文会给出：

- `KIND`：`url`（网页解析）或 `text`（划词 / 粘贴的正文）
- `VALUE`：网址或原文
- `ITEM_DIR` / `MD_PATH` / `SOURCE_NOTE`
- `RESEARCH_ALLOWED`：`true` 时可用 `webfetch` / `websearch` 扩展调研

## 步骤

1. `KIND=url`：先 `webfetch` 该网址，读懂正文；抓取失败就根据标题与 URL 说明失败原因，不要编造内容。
   `KIND=text`：把 `VALUE` 当作一手材料，先提炼它的主张与关键事实。
2. `RESEARCH_ALLOWED=true` 时，针对材料里出现的**具体概念、人物、项目、数据**做 1-3 次检索，
   补齐背景与反例；每个外部结论都记住来源网址。禁止把检索结果当成原文事实。
3. 写 Markdown 到 `MD_PATH`（UTF-8，只写这一个文件）：

```markdown
# <标题：12-24 字，写清调研对象与结论方向>

> 整理日期：YYYY-MM-DD ｜ 来源：<SOURCE_NOTE 或 网址>

## 结论先行

<2-3 句：这份材料值不值得留、核心结论是什么>

## 材料讲了什么

- <要点，带数字/专有名词>

## 背景与延伸

<调研补充的背景、相关项目、对照观点；没有则省略本节>

## 可复用结论

- <以后能直接拿去用的判断或方法>

## 存疑与缺口

<材料没说清、需要核实的地方；没有则写「无」>

## 来源

- <网址 1> — <一句话说明它支撑了什么>
```

4. 写记忆（严格按 rsrs 规范）：先 `rsrs recall "知识库 <主题关键词>" --titles --json --limit 10`，
   再按 **改 ＞ 并 ＞ 挂 ＞ 存** 处理；新建必须带 `--parent`，正文三段：

```text
【前因】<为什么要调研这件事：谁在什么场景下需要>
【行为】<读了哪个网址/哪段文字、查了哪些来源、整理成哪篇文档>
【后果】<得出什么结论、能复用什么、还缺什么>
```

`【行为】` 必须含 `MD_PATH`、原始网址或原文出处、设备（主机名/系统）。
`--importance important`，`--tags "知识库,调研,<主题>,设备绑定"`，写后 `rsrs show <id> --json` 回读。

5. 最后**只输出一行**：

```text
KB_RESULT: {"title":"<标题>","memory_id":"<记忆 id，失败留空>","summary":"<30 字摘要>","note":"<可选说明>"}
```

- `memory_id` 必须从 `rsrs show <id> --json` 的输出里**原样复制完整 UUID**，不要凭记忆手打。
- `summary` 只写调研结论，不要写工具执行情况、命令报错或过程细节。
