## 2. 架构落地

```
presets.js（四套主题 JSON）
      │  engine.applyTheme()
      ▼
:root 上写入 39 个 CSS 变量 + data-theme / data-layout / data-layout-mode
      │
      ├─ tokens.css   令牌默认值 + 旧名别名（--bg-base→--c-bg 等）
      ├─ styles.css   组件规则，仅引用令牌（0 裸色值）
      ├─ layout.css   外壳/区域/分栏骨架
      └─ ui.css       主题面板、纲列表、页签、分段控件
```

**令牌维度**（全部可被用户在面板里改）：
色彩 17 项 · 字体 15 项 · 形状 8 项 · 密度 7 项 · 布局 8 项（区域显隐/分栏/栏宽/面板次序）

## 4. 布局改造

- **右栏常驻 23 纲**：`存到哪里` 与 `主区/日记` 分段同排；搜索分类框；23 个纲平铺直选，**已去掉「人域/AI 域」分组标题**（用户要求）。
- **首屏可容**：23 个标签末行底边 493px < 右栏可视底 512px（480×560 实测），无需滚动即可看全。
- **可用性**：`上级节点`（原「挂哪棵树」搜索）与 `性质标记` 保留为后续层，向下滚动可达——功能零删减。
- **开放布局**：分栏/纵向堆叠、右栏宽 140–260px、顶栏/页签/底栏显隐、面板次序互换，均由主题 JSON 驱动，面板可改。

### 真机发现并已修复的缺陷

**空态误导**：应用冷启动瞬间 rsrs runtime 尚未就绪时，`get_taxonomy` 返回空，界面显示「无匹配分类」，让用户以为是筛选问题。已改为三态区分：
- 无纲标签 → 「分类未加载，需连接 rsrs」
- 有纲但筛选无命中 → 「无匹配分类」
- 正常 → 不显示提示

### 三个窗口的视觉核验（补齐）

| 窗口 | 尺寸 | 结果 | 证据 |
|---|---|---|---|
| 主窗 | 480×560 | 真机 + 预览双通过，四套主题均正常 | `theme-*.png`、`tauri-real-write.png` |

### 真机仍未验证（环境限制，非代码问题）

1. **主题面板点击无法在真机触发**：本机为 wlcom（Wayland）合成 + XWayland，`xdotool` 注入的点击在应用运行一段时间后多次不生效（早期切换视图成功过一次）。因此**真机下的主题切换与外观面板打开未验证**；该路径已在浏览器预览下完整实测（见 §5.4），且真机启动时能正确读出并应用已存主题。
2. 本机整屏抓取恒黑（Wayland 合成），只能按窗口 id 直接抓 X11 窗口。

### 环境副作用说明

- 真机运行期间 memTools 持有 rsrs 记忆库独占锁，导致 CLI `rsrs status` 报 "memory library is locked by another session"。结束应用后恢复。
- 未在应用内提交任何记忆，未改动任何既有记忆数据。
